Metadata Best Practices for SEO Optimization Using PhotoShelter for Brands

Leveraging IPTC metadata fields in PhotoShelter for Brands is essential to an effective SEO strategy for photo departments. This document outlines best practices for using metadata fields to improve discoverability, accessibility, and internal search efficiency.

---

## IPTC Metadata Fields for SEO

The following IPTC metadata fields are indexed by PhotoShelter for Brands and are critical for search engine optimization.

### Description / Caption

**What it does**
Functions as alt text, which is vital for image accessibility and search engine indexing.

**How to use it**

* Write concise, keyword-rich descriptions that accurately describe the image content
* Include relevant event names, sports teams, and locations
* Avoid phrases like “image of” or “picture of”

**Why it’s important**
Alt text is a high-impact SEO field for Google Image Search and is essential for screen readers and accessibility tools.

---

### Title

**What it does**
Describes the image and incorporates keywords for SEO.

**How to use it**

* Use descriptive, unique titles with primary keywords
* Avoid generic titles like `Image01.jpg`
* Prefer meaningful titles such as `University_Sports_Game_April_2025`

**Why it’s important**
Metadata helps search engines understand image content and reinforces the topical relevance of the page.

---

### Keywords

**What it does**
Acts as tags that categorize images by content, theme, or context. Especially useful for large collections.

**How to use it**

* Add specific keywords related to the event, location, subjects, and themes
* Use keyword variations to capture broader search intent
  * Example: `football`, `college football`, `sports photography`

**Why it’s important**
Properly tagged keywords dramatically improve PhotoShelter’s native search efficiency and overall discoverability.

---

### Persons Shown

**What it does**
Indexes images by the people appearing in them, improving name-based search.

**How to use it**

* Include names of prominent individuals (athletes, faculty, speakers)
* Use standardized naming references for consistency

**Why it’s important**
Finding images of specific faculty and staff is difficult without this field being properly populated.

---

### City, State, Country

**What it does**
Provides geographic context that supports local SEO.

**How to use it**

* Always include accurate location information
* Use standardized references

**Why it’s important**
Location context is critical, especially for off-campus events where place matters to usage.

---

### Filename

**What it does**
The actual name of the image file.

**How to use it**

* Use descriptive filenames aligned with image content
  * Example: `University_Football_Game_2025.jpg`

**Why it’s important**
Filenames contribute to both platform search and Google Image Search visibility.

---

## Keyword Taxonomy and Classification Recommendations

Keywords should be organized around  **search intent** . Ask one simple question: *Who is searching for this image and why?*

For institutions like SMU, users typically search by:

* People
* Locations
* Events
* Context

Consistency is the deciding factor between a useful DAM and a digital junk drawer.

### Who

* Use official naming conventions from faculty or staff records
  * Example: faculty bio pages or PeopleID standards
* Departments and schools should use uniform keywords
  * Examples: `Mechanical Engineering`, `Lyle`, `Guildhall`
* Include relevant offices, units, and institutes
  * Examples: `Office of the President`, `Student Affairs`
* For students:
  * Include names only when appropriate
  * Always include a general descriptor and class year
  * Example keywords:
    * `Dallas Hall`
    * `Rotunda Passage`
    * `Class of 2029`
    * `Convocation`

---

### Where

* Location is a primary search driver
* Use user-recognizable building and venue names
  * Examples: `Ford Hall`, `Umphrey Lee`, `Perkins Administration Building`
* Disambiguate similar names clearly
  * Example:
    * `Perkins School of Theology` vs `Perkins Administration Building`
* Add general establishing terms when helpful
  * Examples: `laboratory`, `library`, `cafeteria`, `dormitory`

---

### When

* Critical for annual or recurring events
* Apply consistent keywords at both the file and folder level
* For events occurring multiple times per year, add contextual keywords
  * Example:
    * `Boulevarding`
    * `Clemson`
    * `Football`

---

### What

* Use action-based keywords to describe activity
  * Examples: students studying, faculty lecturing, performances
* Tag seasonal context explicitly
  * Prefer:
    * `Dallas Hall Lawn`, `snow`, `winter`
  * Over:
    * `Dallas Hall Lawn` alone


# Videographer Best Practices

**FY 2024 | Southern Methodist University (SMU)**
**Department:** Development and External Affairs (DEA)

**Last Updated:** March 15, 2024

## Overview

This document defines standardized quality control, technical, metadata, and delivery requirements for all videographers, cinematographers, and post-production editors producing video content for SMU DEA.

Applies to:

* Freelance
* In-house
* Temporary
* Contract videographers and editors

---

## Goal

Ensure consistent, high-quality video capture, editing, metadata, and archival delivery across all SMU video projects.

---

## Video Shooting Guidelines and Quality Standards

### Priority Video Format

* Shoot in **RAW video format with Wide Dynamic Range (WDR)** whenever possible
* Use **high bitrates** (8–10 Mbps minimum)
* Prefer **full-frame sensors**

**Reasoning:** Maximizes flexibility for color correction and editing.

If using crop-sensor cameras:

* Shoot at the **highest available resolution and bitrate**

---

### Alternative Video Format

If RAW is unavailable:

* Shoot in **LOG format** with the highest possible bitrate

Accepted LOG profiles:

* Arri: Log-C
* Canon: C-Log
* DJI: D-Log
* Fujifilm: F-Log
* Nikon: N-Log
* RED: REDlogFilm
* Sony: S-Log
* Panasonic/Lumix: V-Log

**Reasoning:** Ensures color profile consistency across camera types.

---

### Below-Standard Footage (Not Accepted)

Footage will be rejected if it contains:

* Out-of-focus shots
* Unstable camera movement
* Poor framing or composition
* Overexposed or underexposed footage
* Excessive noise or pixelation
* Interlaced video
* Copyrighted or trademarked elements

---

## Resolution, Frame Rates, and Codecs

### Accepted Resolutions

* 4096 × 2160 (4K)
* 4096 × 2304 (4K)
* 3840 × 2160 (UHD)
* 1920 × 1080 (HD)

### Accepted Frame Rates

* 23.98
* 24
* 29.97
* 30
* 59.94
* 60

### Accepted Codecs

* H.264 (≥ 50 Mbps)
* DNxHD
* Apple ProRes 422
* MPEG-4

### Frame Rate Guidance

* **Interviews / direct-to-camera:** 23.98 or 24 fps
* **Live events:** 29.97 or 30 fps
* **B-roll:** 59.94 or 60 fps (prefer 4K)

> Always sacrifice frame rate before resolution.

---

## Shot List Key

All RAW/LOG footage and compressed MP4 copies must be documented.

* Save shot list in the **root folder**
* File name format:
  `CatalogNumberV_ShotListKey`

### Required Shot List Fields

* Clip Name
* Original Filename
* Camera (A, B, C)
* Shot Type
* Movement Type
* Gear
* Location
* INT / EXT + Day / Night
* Sound (Y/N, Stereo/Mono)
* Shot Description
* Subject
* Clip Length (HH:MM:SS)
* LOG / RAW indicator

---

## Deliverables

Submit:

* RAW / LOG footage
* Compressed MP4 copies
* Audio files
* Project files (if final video exists)
* Final exports (if applicable)

---

## Folder Structure

### Root Folder

```
CatalogNumberV-AssignmentName(Initials)MM.DD.YY
```

Example:

```
12345V-CommencementGraduation(GH)12.16.23
```

### Subfolders

```
CatalogNumber_Raw
CatalogNumber_Compressed
CatalogNumber_ProjectFolder
CatalogNumber_Final
CatalogNumber_Audio
```

Notes:

* Root folder uses **dash (-)**
* Subfolders use **underscore (_)**
* Dashes in assignment names are omitted from folder names but retained in metadata

---

## Compressing Files

### Encoding Settings

* Format: H.264
* Preset: High Quality 2160p 4K (customized)
* Match source resolution and frame rate
* Render at maximum depth
* Bitrate: VBR, 1-pass
* Target bitrate: 25–100 Mbps
* Apply Rec.709 LUT
* Set start timecode to `00:00:00:00`

Audio:

* AAC, 48 kHz, 320 kbps

Tools:

* Adobe Media Encoder (preferred)
* HandBrake (acceptable alternative)

---

## Naming Requirements

Applies to:

* Compressed files
* Finals
* Exports
* Audio files

**RAW files must remain untouched.**

### Base Naming Format

```
CatalogNumber_SequentialNumber
```

Example:

```
12345V_001.mp4
```

### Common Extensions

* `_Final`
* `_ED` (edited clip)
* `_TL` (timelapse)
* `_CamA`, `_CamB`
* `_Audio`
* `_Caption`
* `_4K`, `_UHD`, `_1080x1920`
* `_LQ`

### Time Length for Finals

```
_01h00m00s
_01m30s
_30s
```
